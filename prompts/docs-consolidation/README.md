# docs 收敛任务包管道（总结 agent + 提炼 agent + 终审模型）

> 本目录是一套**提示词套件**：把 `docs/**` 的杂乱文档压缩成一份**任务包**，交给高智能模型做最后总结。
> 它**不执行** `TASK-docs-consolidation-zh.md` 的 S1–S7（archive / `git mv` / 提交）。它是那些步骤的**输入准备层**。
> 语料边界（维护者选定）：**仅 `docs/**`**。`MEMORY.md` / `TODO.md` / `OBLIVIONIS.md` 不在本管道输入内；日后需要时按 §9 追加一个包即可。
> 语言约定：提示词中文为主；schema 字段、ABI 名、合同术语、标识符保留英文原文。品牌 `鼠辈啁啾` / `Squeaky Ratkin` 不可改写；中文散文称鼠族。

---

## 1. 管道全景

```
docs/**（26 份，跨时间、互相覆盖、含过期状态）
   │  冻结 revision（记录 git rev-parse HEAD + 文件清单）
   ├─► 阶段 A 总结 agent × 6（并行，一包一实例）
   │      产出 {{OUT_DIR}}/packages/PKG-<n>-<slug>.md      ← 任务包 v1：高召回、强制溯源、四类认识标注
   ├─► 阶段 B 提炼 agent × 1（必要时两轮）
   │      产出 {{OUT_DIR}}/final/handoff-package-v2.md     ← 有损压缩：去重但不抹平矛盾、保留 provenance
   └─► 阶段 C 终审强模型
          产出最终 handoff package（面向维护者 / 执行者）
```

**职责分离（不得互相代做）**

| 阶段 | 职责 | 成功判据 | 失败模式 |
| --- | --- | --- | --- |
| A 总结 | **别漏**：高召回重建决策演化 | 任一决策/反转/事故/未决项都能回指源文件 | 逐文档摘要、把声明写成事实、消解矛盾 |
| B 提炼 | **可验证地减量**：有损压缩但下游不必盲信 | 压缩比达标且矛盾/未决/溯源零丢失 | 为压缩丢未决项、跨包重复只留一份却不登记等价来源 |
| C 终审 | **判断**：独立重建并指出不确定性 | 12 条要求逐条可核 | 复述上游而不挑战、把 `tentative` 写成最佳实践 |

## 2. 硬边界（对所有阶段生效）

1. **只读仓库**：禁止编辑 / 移动 / 删除 / 重命名 `docs/**` 或任何仓库文件；禁止 `git mv` / `commit` / `push` / `tag`；**禁止在 `docs/` 下创建任何文件**。
2. **唯一写入面** = 调度方指定的 `{{OUT_DIR}}`（建议仓库根 `_consolidation/`，临时目录，任务完成后删除，**不提交**）。
3. **不新增检查门**：本管道不写脚本、不改 CI（对齐任务书 §2「文档不新增检查门」）。
4. **隐私写法**：不得把本机绝对路径、盘符形态、日志摘录、凭据、`PublishedFileId` 值写入任何产物；引用一律仓库相对路径。源文档若含此类内容，只描述形态并标注，**不复制原文**。
5. **术语逐字**：版本号、commit/tag、CI run id、hash、文件数、字段名、ABI 键、`SR_*` / `US_*` 前缀原样保留，不做同义改写。
6. **冲突不静默归一**：权威序（§4）只用于**标注**「以谁为准」，不用于删除冲突记录；同一事实的多个时间层必须并存。
7. **产物的可追踪性**：`{{OUT_DIR}}` 必须保持**未跟踪**（临时目录；被 `.gitignore` 覆盖更好），产物不进仓库历史——这**不能替代**任何隐私门：若维护者要求产物入库，必须先过 `scripts/privacy-audit.ps1`（默认模式）再提交。

## 4. 权威分层（仅用于冲突标注）

由高到低：**`AGENTS.md` 操作硬约束 → 三份现行合同 → runbook / 记忆 → 已接受的决策文档与规划输入 → handoff / 检查表 / 评审 / 专项评估 → 历史过程文档与旧 CHANGELOG → 冷归档**。

使用规则：

- 发现「文档 A 与文档 B 冲突」→ 记 `CNF-<n>`，写清双方要旨、来源、**时间层**（各自写作时点）、可能的解释（标 `[I]`）、建议回查点；**不得**只留"以合同为准"一句。
- 发现「同一文档内部不同段落互相矛盾」→ 同样记 `CNF`，并标注该文档的时间分层（例：`handoff-0.3.3-zh.md` §1–§9 写于 2026-08-23「本轮 0 提交」，§10 写于 2026-09-13「工作树已提交」）。
- 权威序只决定**"若必须选一个，建议以谁为准"**；冲突本身必须保留给下游模型重新判断。

## 6. 模型分工与执行顺序

| 阶段 | 实例数 | 建议模型档位 | 上下文 | 备注 |


   > 若清单外出现新增文件：按主题并入最接近的主包，或新开 `PKG-7+` 并在 §3 / §5 登记——不得静默遗漏。

3. **编排方覆盖校验**（§7）：任一文件未被任何包声明 → 打回对应包补充；**不得**带着缺口进入阶段 B。

## 7. 覆盖校验（编排方手工核对，非仓库门禁）

- **基准**：§3 的 26 文件清单（按冻结 revision 复核后的版本）。
- **判据**：每个文件必须满足其一 —— (a) 是某包主源，且该包 §0 声明「已吸收章节」或「明确未吸收 + 理由」；(b) 未出现在任何包中 → **FAIL**，补包或补声明。
- **记录**：写入 `{{OUT_DIR}}/coverage-check.md`（只写结论与差异，不复制文档内容）。
- **核对手段**：用文件系统核对（`Test-Path` / `Get-ChildItem`），**不要用 `git status`**——本仓 `.gitignore` 含 `packages/` 规则，会把产物静默隐藏（见 §10）。
- **覆盖 ≠ 摘要**：包允许对"无决策价值的例行状态"声明未吸收，但必须逐条给理由；不允许整体跳过。

## 8. 验收抽查（人工，约 5 分钟）

1. **溯源可回指**：随机抽 5 条 v2 结论，按 `src:` 回指源文件章节/行，核对语义未被扭曲。
2. **数值逐字**：抽 3 个数字/标识符（版本号、commit、hash、键名、文件数）逐字比对。
3. **矛盾仍在**：至少找到 1 组被保留的 `CNF` 或反转（不允许被"最新口径"抹平）。
4. **隐私零命中**：产物中无盘符形态、无本机绝对路径、无凭据、无 `PublishedFileId` 值。
5. **压缩结构合理**：按 §8.7 的达标线核对（严格档 / 密度举证档；见 02 §4 三线判据），且预算集中在决策史/矛盾/未决，而非均匀压缩（任务要求 5 / 11）。
6. **不确定性可见**：v2 能指出自己拿不准的地方（`[C]` / `[I]` / `[U]` / `GAP` 均非空）。
7. **达标线与返工**：严格档 = `v2 ≤ min(0.25·全语料, 0.60·Σ输入)`；若 §0 举证逐字保留面占 v2 的 ≥50%，放宽档 = `min(0.30·全语料, 0.75·Σ输入)`。未达线且无举证 ⇒ 编排方**打回重跑**（换档位或改 `two-pass`）。实测校准：两次完整运行落在 Σ输入的 71–81% = 全语料的 28–32%，即落在放宽档内、严格档外——说明「密度例外」对标识符密集的语料是常态，编排方应先核举证档位再判是否返工。

## 11. 常见失败模式与纠正

| 失败模式 | 表现 | 纠正 |
| --- | --- | --- |
| 逐文档摘要 | 包按文件分节，决策史破碎 | 包内按「时间线 + 决策账本」主题化重建；文件只出现在 §0 覆盖声明与 §12 未吸收 |
| 声明升格为事实 | 维护者口径 / agent 声称写成事实 | 强制 `[F]/[C]/[I]/[U]` 标签，且 C 必须带出处人称与时间 |
| 消解矛盾 | 冲突被"最新口径"覆盖 | `CNF` 只标注不删除；权威序仅给"建议以谁为准" |
| 丢 provenance | 结论无 `src:` | 每条 `DEC/ASM/INC/CNF/OQ/LES` 至少 1 个 `src:` |
| 为压缩丢未决项 | Q1–Q10 类清单被折叠 | `OQ` / `GAP` 属不可压缩面，预算下限保护 |
| 表达层未压缩 | v2 ≥ Σ输入包（甚至更大），只做记账不做压缩 | §4 七条压缩手法 + 三线判据（§8.7）；P0 保条目、不保原文 |
| 把 handoff 当现行状态 | 旧交接的"当前"被当事实 | 时间层标注：写作时状态 vs 后续变化 |
| 跨包重复三选一 | 同一事实跨包被合并成一份却丢等价来源 | 保留信息量最大一份 + 登记其余等价来源 |
| 把 token 花在例行状态 | Claim Pack 哈希表大段复制 | 发布事实保留"版本→渠道→结论→证据指针"一行制，细节留源文件 |
