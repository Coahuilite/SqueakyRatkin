## 1. 决策摘要

重构应围绕玩家要完成的任务，而不是围绕设置字段、C# 类或现有绘制顺序。普通玩家固定看到三个顶级 Tab；七击解锁开发者工具后，出现第四个 Tab：

1. **发声规则**：是否发声、何时发声、频率与距离；
2. **心情音色**：心情如何改变已播放声音的音高与音量；
3. **语音来源与异种**：声音包来源、Fallback/Remix 选择，以及可选的异种覆盖。
4. **开发与诊断**（隐藏）：仅在现有七击解锁状态生效后显示，收纳日志、统计、音频路径、音频浏览器、版本/构建信息和关闭开发者工具。

未解锁时不显示占位、锁图标、悬浮提示或其他入口暗示；解锁后它是普通的第四个导航项，不通过浮窗或 hover 菜单承载功能。

实现以 RimWorld/Unity IMGUI 的 `Rect` 布局为中心：先测量、再排列、最后绘制；根据实际可用宽度和高度切换有限模式；每个滚动区有明确所有者。优先修复本模组页面，只有出现可验证的跨模组复用证据才考虑提取 source/shared project。

## 2. 截图已经暴露的真实问题

以下是本 Draft 要解决的已观察布局与交互风险，不应被“静态代码已修复”或“能编译”替代为完成声明：

| 页面 | 暴露的问题 | 对玩家的影响 |
| --- | --- | --- |
| Basics / 发声规则 | 展开的动作区留下空白，后续内容不可达或看似不可达。 | 玩家无法确认或修改全部动作规则，容易误以为设置丢失。 |
| SoundMood / 心情音色 | 普通尺寸下勉强可用，但列宽与留白失衡。 | 关键数值、标签和控件的关系不清，缩放或翻译后风险放大。 |
| Xenotype / 语音来源与异种 | 顶部管理区、列表、编辑器出现多重滚动；低高度/窄宽下裁切，tooltip 还会遮挡目标。 | 玩家可能滚到错误区域、无法到达编辑项，或因帮助浮层遮住控件而误操作。 |

这些问题是可观察的玩家任务失败，不是单纯“视觉不够整齐”。最终是否关闭问题必须由目标语言、缩放、宽高、滚动与点击的实机验证决定。

## 3. 冻结的业务边界（不得借 UI 重构改变）

本 Draft 只调整信息架构、布局、帮助和页面内部组织。以下产品语义冻结：

- 所有业务设置在语义输入改变后**即时生效**；不存在草稿交易。
- 保存使用约 **350 ms** 的 coalesced save；关闭窗口时 flush 最新待保存值。保存状态应如实表达 Saving / Saved / Failed；失败代际保留 pending，但不无限自动重试。
- Saving / Saved / Failed 使用窗口外壳中永久预留的固定状态槽，不参与导航或页面高度计算。普通“已保存”不显示 `?`；需要操作的失败信息可提供详情，但不得引起布局重排。
- Remix 保留已有的**两步确认**与输入穿透防护；取消任一步都不得改变模式。
- 主菜单是受支持能力边界：无可玩地图时，页面仍安全可打开；依赖地图、选择 Pawn 或 MapUI 的功能明确降级并说明原因，不直接访问这些服务。
- **No-DLC baseline** 不变：无 Biotech 时不得读取 Xenotype DefDatabase 或 Pawn genes；基础设置、保存、动作、心情与 Race/Vanilla 回退仍可用。
- 不增加 Apply、Revert、dirty-close guard 或任何隐式事务；不改变既有产品语义、Scribe 兼容、resolver 选择、动作资格或音频回退规则。

## 4. 玩家任务导向的信息架构

### 4.1 顶级 Tab

推荐稳定命名为：**发声规则 / 心情音色 / 语音来源与异种**。名称描述玩家决策，而非“Basics”“SoundMood”“Xenotype”等内部分类；实现中的旧枚举、字段或 partial 名称不要求同步改名。

### 4.2 Tab 1：发声规则

**首屏目标：**玩家打开即能知道“是否启用、总体频率/距离如何、下一步在哪里调单个动作”。

建议顺序：

1. **总开关与即时状态**：全局启用、Talking/全局冷却等直接影响“会不会叫”的选择；必要时显示生效说明。
2. **距离与频率**：距离预设/自定义范围、全局冷却等高频任务。距离图和文字说明按实际可用宽度测量；窄宽时标签在上、控件在下。
3. **动作规则**：动作 scope、间隔、概率等，以稳定表格或窄宽纵向行显示。它是核心任务，不归入“高级”；首次打开可默认展开，之后保留本次窗口会话中的折叠状态。折叠标题必须显示摘要（例如动作数或当前模式），展开后在同一帧获得正确内容高度。
4. **辅助设置**：只保留普通玩家可能需要的低频设置。开发者工具、详细日志、版本/构建身份与诊断面板移入解锁后出现的第四个 Tab。

频率区中，“按可听鼠量缩放周期声音”作为默认启用开关，与现有“按游戏倍速缩放冷却”并列。它只控制大规模可听候选数量对 Periodic 概率/时间间隔的缩放；一次性的非持久化 Periodic 启动相位是独立运行时安全行为，不受该开关控制。

页面使用一个主滚动区；折叠、展开、内容减少后必须夹紧 scroll position，不能留下旧高度造成的动作空白或不可达内容。

### 4.3 Tab 2：心情音色

**首屏目标：**玩家先看到当前全局音色与其立即生效，再决定是否展开细调。

建议顺序：

1. **全局心情音色摘要**：说明其会影响播放时的音高/音量，而不改动作频率、资格或声音包选择。
2. **全局调节**：心情相关的主要 slider/数值，宽屏可用统一 label/control 两列；列宽从控件最小宽度和文本测量推导，不按截图比例硬编码。
3. **分段/覆盖细调**：需要更多解释或较少使用的 mood override 置于后方，默认可折叠。
4. **试听与帮助**：试听属于明确命令，和持久 selector 区分；无地图或无目标时给出能力说明，不冒充可执行。

普通尺寸“勉强能塞下”不是布局模式。应明确 normal 与 narrow 两种排列：normal 保证可读的两列；narrow 纵向堆叠，避免压缩控件、失衡留白或列间抢宽。

### 4.4 Tab 3：语音来源与异种

**首屏目标：**先告诉玩家当前声音来源策略及当前可用性，再让其管理包或异种覆盖。

建议顺序：

1. **来源策略**：Off / Fallback / Remix 与当前摘要；Remix 进入既有两步确认流程，确认前不改 canonical 值。
   - 无 Biotech 时必须按当前模式准确说明：Off 只用 Vanilla；Fallback 为 Race → Vanilla；Remix 在当前可播放的 Race 与 Vanilla 层之间等权选择。共同边界只说明语音包不改变频率、资格、距离或 Mood。
2. **声音包与 Catalog 管理**：可用、空、失败、dormant/orphan 等状态与刷新、选择、忘记等操作；这是管理区，不与编辑器争夺同一不受控滚动空间。
3. **异种覆盖编辑**：仅在 Biotech 能力存在时提供；否则显示不可用及 Race/Vanilla 继续工作的明确说明。异种技术身份仍是精确、区分大小写的 `XenotypeDef.defName`，本页只改善呈现，不改变资格判断。
   - 精确 `defName` 冲突时，只有该 Xenotype 身份、该层覆盖与新分配 fail closed；全局行为以及 Race/Vanilla 降级继续工作，文案不得扩大为整个播放关闭。
4. **高级诊断/技术信息**：来源、defName、解析原因等收纳在次级区或可点开的详情中，避免占用普通玩家首屏。

## 5. IMGUI 响应式实现方向

### 5.1 有限宽高模式，而不是无限自适应承诺

每页根据传入可用 `Rect` 的**有限**宽度与高度模式安排，例如 normal、wide-low、narrow-high、narrow-low。breakpoint 由标签、控件和 scrollbar gutter 的最小可用尺寸推导，而非根据某张截图调比例。高度不足是独立维度：宽屏不代表顶部管理区和编辑器同时足够高。

所有页面应预留固定 scrollbar gutter，避免滚动条出现/消失时列宽跳动。每种控件有明确最小宽度与最小高度；无法满足时切换为堆叠、分页或滚动，不生成负宽度、重叠 Rect 或不可点击热区。

### 5.2 Measure → Arrange → Draw

页面布局遵循纯粹的三步：

1. **Measure**：以当前语言、可用宽度、可见 section 与模式计算文本高度、行高、内容高度和最小宽度；不写设置、不刷新 Catalog、不播放声音。
2. **Arrange**：把已测量结果分配为 header、section、列表、编辑器和固定 gutter 的 `Rect`；此步骤决定滚动区边界与所有权。
3. **Draw**：仅在已分配 Rect 内画控件、读取输入并返回/处理本页既有的语义变化；恢复 IMGUI 全局状态，保证 Begin/End 成对。

测量和排列应可由相同输入得到相同输出，不能通过“先画一次猜高度、再离屏画第二次”修补。文本语言、UI scale、宽度、展开状态或数据 revision 改变时，相关 measurement cache 必须失效。

### 5.3 滚动所有权

- Tab 1、Tab 2：一页一个主 scroll，页面负责其 content rect、position 与 collapse 后 clamp。
- Tab 3：顶部管理区压缩为固定摘要，不拥有垂直滚动；master 列表和 detail 编辑器在边界、视口裁切明确时各自滚动。不得让同一个鼠标滚轮事件同时推动多层。
- 宽屏 Tab 3 只有左右列各自拥有滚动状态；低高度时顶部管理区隐藏长说明、压缩模式选择与 Catalog 状态，把剩余高度让给左右 pane，而不是增加第三个滚动区。
- 窄屏 Tab 3 不以“把三个滚动区竖排”解决问题，而是转为列表步骤与编辑步骤，保证当前任务只有一个主要滚动所有者。

## 6. 四页响应式草图

下图是结构草图，不规定最终视觉 token、像素或控件皮肤。

## 7. 帮助信息层级

- tooltip 只放**短、即时**说明：术语解释、禁用原因、完整被截断文本或单句风险提示。
- 较长的机制、回退顺序、No-DLC 边界、Remix 含义与技术标识说明，使用可见的 **`?`** 点击后在页面内展开/显示的长帮助；不要让 hover tooltip 承载关键知识。
- `?` 的 hit rect 与相邻 selector、列表行、Forget 等动作严格不重叠；仅消费起始于自身 rect 的 MouseDown，避免 tooltip 点击同时选行、切换或触发命令。
- 长帮助应在所属 scroll/view 的裁切规则内排列，不能覆盖正在操作的按钮；必要时占用正常内容高度，而不是悬浮遮挡。

## 8. 代码组织：YAGNI 收缩方案

本次不建立抽象 UI 平台。为固定四页服务的最小组织建议是：

- 固定四页的实现可保留为现有类中的 **partial**，或在不扩大边界的前提下按页拆分；不要求重命名领域类型。
- 每个页面保有自己的 `Rect`、测量结果、展开状态与 scroll position；页面本地处理其有限布局模式和测量 cache。
- 现有 `SqueakySettingsUI` 只收敛为**精简静态工具箱**：无领域写入的常用 Rect、截断/短帮助、稳定的控件尺寸或绘制辅助。它不成为状态容器，也不负责设置保存、Catalog 或 resolver。
- `SqueakSettingsGameContext` 继续是领域专用的主菜单/游戏内能力边界；保存协调器继续是本项目 immediate + coalesced save + flush 的领域协调器。

明确不提议：`Layout/Controls/Pages/State` 四层框架、`ISettingsPage`/router、通用 store/command bus、布局 DSL，或为假设中的未来模组预先创建通用状态管理。它们会把当前的四页修复扩张为未证实的产品架构。

## 9. Keep / Defer / Reject

| 分类 | 内容 | 理由 |
| --- | --- | --- |
| Keep | 三个固定任务 Tab、immediate 生效、350 ms coalesced save、close flush、Remix 两步确认、主菜单能力边界、No-DLC 回退。 | 已签署的产品/兼容边界，布局不能推翻。 |
| Keep | 页面本地测量、Rect、scroll state；`SqueakySettingsUI` 精简静态 helper；领域专用 Context/保存协调器。 | 足以修复已知四页问题，依赖面小。 |
| Defer | 跨模组 source/shared project、可复用 Core-only Rect/helper 集。 | 先要有真实重复和真实共享修复证据。 |
| Defer | 更广泛的视觉 token、通用组件契约或其他页面的改造。 | 可由后续已授权工作独立决定，不是本 Draft 的实现前提。 |
| Reject | Apply/Revert、dirty-close、草稿交易。 | 与当前全 immediate 产品语义冲突。 |
| Reject | `Layout/Controls/Pages/State` 四层框架、`ISettingsPage`/router、通用 store/command bus、布局 DSL。 | 当前只有固定四页；抽象成本和 API 负担大于已证实收益。 |
| Reject | 用多层嵌套 scroll、截图特调比例或 tooltip 覆盖来掩盖空间不足。 | 不解决滚动所有权、可达性和输入冲突。 |

## 10. 跨模组框架的晋级证据门槛

在满足以下全部证据之前，保持实现为本项目本地 helper，不把它宣传或实现成共享框架：

1. 至少 **两个独立、已发布的模组**出现基本相同的 **5–10 个 Core-only、纯 `Rect`/helper** 需求；这些 helper 不读取本模组 settings、DLC、DefDatabase、Catalog、resolver 或保存状态。
2. 存在至少一个**真实共享 bug fix**：同一 helper 的修复被两个模组实际采用，并解决了同类问题，而不是复制代码后“理论上可共享”。
3. 至少经历**一个发布周期**，两方对 helper API 没有分叉、没有各自加领域参数，也没有为兼容而互相锁版本。
4. 满足后先尝试 **source/shared project** 共享，并由各模组随自身发布构建；不先发共享 DLL，不引入运行时硬依赖或版本协调负担。

任何一项缺失时，结论都是“继续本地化”，而非“先造框架等待复用”。

## 12. 验收矩阵与验证范围

### 12.1 布局矩阵

每个组合都覆盖三个普通 Tab，并在解锁后覆盖“开发与诊断”第四 Tab；不以“同一布局截图看起来正常”替代点击验证：

| 语言 | UI Scale | 窗口/可用区域模式 | 必测重点 |
| --- | --- | --- | --- |
| EN、SC | 100%、125%、150% | normal | 标签、列、首屏任务、完整文本恢复。 |
| EN、SC | 100%、125%、150% | wide-low | 顶部管理区高度、Tab 3 pane 裁切/独立滚动、内容可达。 |
| EN、SC | 100%、125%、150% | narrow-high | Tab 1/2 堆叠、Tab 3 列表/编辑分步、控件最小宽度。 |
| EN、SC | 100%、125%、150% | narrow-low | 最高风险组合：主 scroll、步骤切换、折叠后 clamp、无重叠/无不可达。 |

### 12.2 场景与行为验证

- **主菜单：**三个普通页均可打开；解锁后第四页也可安全打开。无地图/选择 Pawn 时，依赖功能显示正确不可用原因，不出现 `Find.TickManager`、`Find.Selector`、`Find.MapUI` 等游戏上下文访问故障。
- **游戏内：**有地图、可选 Ratkin、无选择、不同声音包/Catalog 状态下检查首屏、列表、编辑器、试听和帮助。
- **No-DLC：**关闭官方 DLC 后，页面、保存、全局规则和心情音色仍工作；异种入口安全降级；不读取 Biotech DefDatabase/genes；Race/Vanilla 回退语义不变。
- **scroll：**折叠/展开、切换 Tab、切换 Tab 3 的列表/编辑步骤、低高度与长列表后，没有 GUIClip、Begin/End ScrollView 不匹配、滚动串层或不可达控件。
- **input：**slider 拖动、文本输入、按钮、列表选择、`?`、Remix 两步确认以及取消/关闭均无穿透；帮助不遮挡目标操作。
- **save：**所有业务设置立即反映到运行时；快速连续输入合并为约 350 ms 保存；关闭时 flush；重开/重启保留；Failed 状态诚实且不无限重试。
- **log：**实机日志没有本设置窗口引起的 NRE、InvalidCast、GUIClip、ScrollView mismatch 或 Unity main-thread 错误；日志语义与既有协议不因 UI 重构改变。
